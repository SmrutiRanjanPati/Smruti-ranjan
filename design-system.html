Design Systems

Enterprise Design System

Different product teams had quietly built their own versions of the same button, the same card, the same table row - each slightly inconsistent, each slower to hand off than it needed to be. This is how that got consolidated into one system teams actually adopted.

Role

Design Systems Owner / SME

Client / Team

Digitus Business Solution

Timeline

Nov 2025 – Present

Tools

Figma

Share: LinkedIn X Email

The challenge

An audit across active products turned up several near-duplicate versions of common components, each with its own spacing and color logic. Front-end handoff meant re-explaining the same decisions project after project.

Accessibility wasn't consistently considered at the component level, which meant it had to be caught - or missed - late, per project.

Process

  • Audited existing UI across teams to find which patterns were genuinely reused versus one-offs worth retiring.
  • Defined a token layer for color, spacing, and type so every component inherited the same base decisions.
  • Built the component library in Figma with documented variants and usage guidance, not just visual states.
  • Ran workshops with cross-functional teams as design SME, walking through WCAG accessibility standards baked directly into each component.

Solution

A token-driven component library covering the core UI vocabulary - buttons, cards, form fields, tables, status indicators - each shipped with accessibility behavior already handled.

Documentation focused on when to use a variant, not just how it looks, so teams could self-serve instead of asking design for every decision.

Results

Reduced front-end development time by roughly 30% by removing repeated one-off component builds.

Became the shared reference for visual consistency across enterprise-facing products.
